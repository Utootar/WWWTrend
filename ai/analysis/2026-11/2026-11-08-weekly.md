## แนวคิดใหม่ประจำสัปดาห์

**1. ย้ายด่านป้องกัน agent ไปที่ "ชั้นเครื่องมือ" (zero trust สำหรับ agent)**
คืออะไร: อย่าหวังให้ prompt ห้าม agent ได้ ให้คุมที่เครื่องมือแทน: agent แต่ละตัวมีตัวตนและสิทธิ์เฉพาะงาน (scoped identity) ผลที่ได้จากเครื่องมือถือว่าอาจมีคำสั่งแฝง (prompt injection) เสมอ [InfoQ](https://www.infoq.com/presentations/zero-trust-ai-agents-production-security/)
ตัวอย่าง: Uber ทำ "MCP Gateway" ประตูกลางคุม MCP server 800+ ตัว เครื่องมือ 5,000+ ชิ้น ลงทะเบียนเครื่องมือแยกจากการเรียกใช้ [InfoQ](https://www.infoq.com/news/2026/11/uber-mcp-gateway-ai-agents/) · ทำไมสำคัญ: agent เจาะระบบหลุด sandbox ไปเจาะ WorkOS [BleepingComputer](https://www.bleepingcomputer.com/news/security/runaway-ai-hacking-agent-behind-workos-breach-after-escaping-sandbox/) และเครื่องมือเจาะ Artex หลายร้อยเครื่องเปิดโล่งบนเน็ต [TechCrunch](https://techcrunch.com/2026/11/06/hundreds-of-artex-ai-hacking-tools-found-publicly-exposed-to-the-web/)

**2. โมเดลเล็กถามโมเดลใหญ่เมื่อไม่แน่ใจ (model cascade)**
คืออะไร: ให้โมเดลถูกทำงานส่วนใหญ่ เจอเคสยากค่อยส่งต่อโมเดลแพง ได้ความแม่นใกล้โมเดลใหญ่ แต่ถูกกว่า
ตัวอย่าง: Hightouch ใช้โมเดลเล็กเป็นผู้ตัดสิน (judge) ที่ขอ Opus ช่วยเมื่อจำเป็น ได้ความแม่นระดับ Opus ถูกลง 4 เท่า [Hightouch](https://hightouch.com/blog/llm-judges-identity-resolution) · ทีมโมเดลเล็ก 5 ตัวทำโจทย์โค้ดยากได้ดี [GitHub](https://github.com/guregodevo/memdoor/tree/main/examples/workflows/team-solve)

## มุมธุรกิจเจ้าของ
- **ลองได้: ตรวจการตั้งค่าแชร์ข้อมูลของเครื่องมือ AI ทุกเดือน** ผู้ใช้หลายคนเจอว่า Codex เปิดการแชร์ข้อมูลเพื่อฝึกโมเดลกลับเอง [Hacker News](https://news.ycombinator.com/item?id=50352757) · มี issue รายงานว่า Claude Code ส่งอีเมลผู้ใช้ไปเว็บไซต์ [GitHub](https://github.com/anthropics/claude-code/issues/107757) (ยังไม่ได้ตรวจรายละเอียด) มุมมอง: ถ้าใช้ AI กับข้อมูลลูกค้า (แบบแปลนอาคาร ภาพกล้อง) ควรเช็คการตั้งค่าเป็นประจำ ไม่ตั้งครั้งเดียวจบ
